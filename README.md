# Adaptive Storage Neolithic Module Renew

Port of **Soul, Phaneron and bradson's Adaptive Storage Neolithic Module** to RimWorld 1.6.

**I am not the author of this mod.** The buildings, their artwork and their stats are theirs — all
I did was the work needed to make the module run on 1.6, and fix what the port turned up. Credit
goes to them; mistakes in the port are mine.

Original mod: https://steamcommunity.com/sharedfiles/filedetails/?id=3033901895 — declares 1.4 and
1.5 and nothing further.

**MIT licensed by its authors.** Unlike most ports in this repository, this one rests on written
permission rather than on an author's silence. See [ATTRIBUTION.md](ATTRIBUTION.md) and
[LICENSE](LICENSE).

## What the mod does

Tribal storage for the [Adaptive Storage
Framework](https://steamcommunity.com/sharedfiles/filedetails/?id=3033901359): containers that
show what is inside them. Fill a basket and you watch the basket fill up.

Nine buildings are written out by hand:

| Building | Built from | Holds |
|---|---|---|
| Basket (woody) | 20 wood | anything |
| Basket (fabric / leather) | 20 fabric or leather | anything |
| Large pot | 20 wood | raw food, kibble, pemmican |
| Meal shelf | 20 wood | meals |
| Hay pile | 10 wood + 75 hay | hay |
| Wood pile | 20 wood | that same wood |
| Textile bundle (fabric) | 30 fabric | that fabric |
| Textile bundle (leather) | 30 leather | that leather |
| Plinth (woody) | 40 wood | one item, on display |

Eighteen more are generated by patch, three per stone chunk in the game — a large pot, a plinth
and a stacked-chunk barricade for granite, sandstone, limestone, slate, marble and, with Odyssey,
vacstone. The plinths carry `CompProperties_Art`, so they take a quality and get a name and a
description like any other art.

Two neolithic research projects unlock the set, 400 points each, both tagged `TribalStart`, in the
framework's own Storage research tab.

Available in English, French and Russian.

Content mod: removing it mid-save destroys any of these containers already built, and drops what
was inside them.

## Requirements

- **[Adaptive Storage
  Framework](https://steamcommunity.com/sharedfiles/filedetails/?id=3033901359)** by Soul, Phaneron
  and bradson — supports 1.4, 1.5 and 1.6. The module does nothing without it.

Odyssey is optional. Without it you get fifteen generated buildings instead of eighteen.

## What changed in the 1.6 port

Very little, and that is the honest answer. Three quarters of this mod is declarative graphics
carried by the framework, and the framework already supports 1.6 — so there was no API to chase.

**No def needed rewriting.** Every XML element still maps to a field that exists on the 1.6 class,
checked by reflection against RimWorld's `Assembly-CSharp.dll` and the framework's 1.6 assemblies:
28 files, zero unknown fields. Every C# type the XML names is still there too.

**Two faults were fixed on the way through**, neither of them caused by 1.6:

### The Russian translation was invisible on Linux

`Languages/Russian/Definjected/` — lowercase `i`. RimWorld looks for the exact string
`DefInjected`. On Windows, NTFS ignores case and it worked by accident; on a case-sensitive
filesystem, which includes the Steam Deck, the folder is simply not found, the game falls back to
English, and nothing is logged. Renamed.

### French did not know about vacstone

1.6 added a sixth stone chunk with Odyssey. The three patches generate from every child of
`ChunkRockBase`, so the mod picked it up on its own — but the French translation was written when
there were five, and the three vacstone buildings came out in English. Six keys added, using
RimWorld's own French for *vacstone*: **vaccolithe**.

Russian still covers five. I do not write Russian, and a fabricated translation would be worse
than a visible gap — a Russian speaker is welcome to send the six keys.

**`packageId`** is now `nelim.adaptivestorageneolithic`, and the original is declared in
`<incompatibleWith>`: both mods use the same `defName`s, so running the two together would
duplicate all 71 defs. The `defName`s being identical is also what lets a save move between them.

## Repository layout

```
Mod/     the published folder — this is what the junction into RimWorld/Mods points at,
         and what Steam uploads, unfiltered
Art/     source material kept out of the upload: the original preview, and the nine
         shelved textures the mod never loaded
```

`Mod/LICENSE` is not a stray duplicate. MIT requires the notice to accompany every distribution,
and Steam ships the contents of `Mod/` and nothing else.
